# FIC 2.0: передача контекста

Этот файл хранит текущее состояние работы между чатами. Он не является журналом
всей разработки и не заменяет `AGENTS.md` или архитектурную документацию.
Следующий агент должен сначала прочитать этот файл, затем проверить фактическое
состояние через `git status`.

## Текущий снимок

- Обновлено: 2026-06-28.
- Ветка: `main`.
- Базовый commit: `4ef68ed`.
- Текущая задача: реализовать улучшение интерфейса вкладки `Контроль устройств`
  в `fic-gui` по согласованному UX-плану.

## Сделано

- В `DeviceTree` добавлены строка поиска, быстрые фильтры по статусу/типу
  устройства и счетчик показанных/загруженных устройств.
- При активном фильтре дерево раскрывает уже доступные ветки, чтобы найденные
  устройства не оставались скрытыми внутри нераскрытых родителей.
- Статусная колонка дерева стала компактнее: `Блок`, `Разреш.`, `Пост.`,
  `Игнор`, с цветовым выделением и сохранением подробностей в tooltip.
- Для строк дерева добавлены иконки по базовым типам устройств и метаданные для
  фильтрации без дополнительных IPC-запросов.
- В контекстное меню устройства добавлено действие `Копировать devpath`.
- В правой панели добавлены видимые элементы управления выбранным устройством:
  уровень контроля, флаг действия во всей системе, сброс правила, копирование
  пути и копирование сводки.
- Правая нижняя область заменена на вкладки `Параметры` и `События`.
- Добавлен новый `DeviceEventList`, который читает существующую IPC-команду
  `device_events` и показывает последние события выбранного устройства.
- В `DeviceAttributeList` добавлен поиск по параметрам и счетчик видимых строк.
- Обновлена `docs/architecture-diagrams.md`: GUI теперь явно связан с
  `device_events`.

Не выполнялось:

- runtime-запуск `fic-dick --daemon`;
- реальные udev trigger, policy apply, lock/unlock, device mutation;
- запись в `/opt/fic`;
- сборка deb/rpm пакетов.

## Риски и что проверить в runtime

- Фильтр дерева при активном поиске раскрывает загруженные ветки и может
  выполнить серию `device_children` IPC-запросов на больших деревьях.
- Нужно визуально проверить вкладку на 1280x720, 1366x768 и 1920x1080:
  ширину дерева, правые элементы управления, вкладки параметров/событий.
- Нужно проверить сценарии управления с выбранным устройством:
  изменение уровня контроля, `Во всей системе`, сброс правила и обновление
  summary после ответа daemon.
- Нужно проверить поведение при недоступном `fic-dick --daemon`: дерево,
  параметры и события должны оставаться диагностичными, без падения GUI.
