# fic-gui

`fic-gui` - графический клиент FIC 2.0 для просмотра и изменения настроек политик. Компонент предоставляет пользовательский интерфейс, но не владеет конфигурационными файлами напрямую.

## Назначение

GUI предназначен для удобного изменения значений политик и их состояния. В новой архитектуре `fic-gui` не пишет в `/opt/fic/config` самостоятельно. При нажатии применения изменений он отправляет команды демону `fic` через Unix-сокет.

Это сохраняет единый источник изменений: daemon API. Благодаря этому CLI, GUI и периодическая проверка работают через одну модель состояния.

## Основные возможности

`fic-gui` предоставляет:

- графический просмотр модулей, подмодулей и политик;
- редактирование значений политик через специализированные редакторы;
- включение и отключение политик;
- отправку изменений демону через команды `set_policy_value`, `enable_policy`, `disable_policy`;
- просмотр логов и фильтрацию записей;
- отображение информации об устройствах из базы FIC.

## Взаимодействие с демоном

GUI использует общий IPC-клиент:

```text
fic-common/fic-ipc/include/fic/ipc/FicIpcClient.h
```

По умолчанию подключение выполняется к:

```text
/run/fic/fic.sock
```

Для разработки путь можно переопределить:

```bash
FIC_SOCKET_PATH=/tmp/fic.sock fic-gui
```

Для device API используется отдельная переменная `FIC_DEVICE_SOCKET_PATH`.
Она не подменяется значением `FIC_SOCKET_PATH`, чтобы тестовый policy daemon
нельзя было случайно принять за привилегированный device endpoint.

## Применение изменений

При сохранении изменений GUI проходит по списку измененных политик и для каждой политики выполняет две операции:

1. Отправляет новое значение:

```json
{"command":"set_policy_value","module":"<module>","policy":"<policy>","value":"<value>"}
```

2. Отправляет новое состояние политики:

```json
{"command":"enable_policy","module":"<module>","policy":"<policy>"}
```

или:

```json
{"command":"disable_policy","module":"<module>","policy":"<policy>"}
```

Если демон возвращает ошибку, GUI показывает пользователю текст ошибки и не считает изменение успешно примененным.

После применения политик GUI показывает сводку ответа демона, а в раскрываемом
поле Details — результат и диагностические записи каждого вызова
`Policy::apply()`. Диагностика учитывает настроенный уровень логирования;
достижение лимита ответа отмечается строкой `... diagnostics truncated`.

## Что GUI не должен делать

`fic-gui` не должен:

- напрямую писать в `/opt/fic/config`;
- самостоятельно применять политики к ОС;
- обходить daemon API для включения, отключения или изменения значений политик;
- требовать прав на запись к системным конфигам FIC, если эту работу может выполнить демон.

## Runtime-зависимости

Для полноценной работы требуется запущенный демон `fic`.

Проверить демон можно через CLI:

```bash
fic-cli status
```

Если используется нестандартный сокет:

```bash
FIC_SOCKET_PATH=/tmp/fic.sock fic-cli status
```

## Сборка

Из корня проекта:

```bash
cmake -S . -B build-check
cmake --build build-check --target fic-gui
```

Отдельная сборка компонента:

```bash
cmake -S fic-gui -B build-fic-gui
cmake --build build-fic-gui
```

## Зависимости

Компонент использует:

- C++17;
- Qt Widgets;
- SQLite3;
- OpenSSL;
- nlohmann/json;
- общие классы модулей, политик и утилит FIC.

## Упаковка

В deb/rpm packaging графический компонент устанавливается как:

```text
/opt/fic/bin/fic-gui
```

При bundle-сборке Qt реальный бинарный файл устанавливается как:

```text
/opt/fic/bin/fic-gui.real
```

а `/opt/fic/bin/fic-gui` является launcher-скриптом, который выставляет Qt-переменные окружения и запускает реальный бинарник.

## Связанные файлы

- `fic-gui/src/main.cpp` - точка входа приложения;
- `fic-gui/src/mainwindow.cpp` - основная логика окна и применения изменений;
- `fic-gui/src/policy` - редакторы политик;
- `fic-gui/src/wrappers` - Qt-обертки над общей логикой;
- `fic-common/fic-ipc/include/fic/ipc/FicIpcClient.h` - IPC-клиент для связи с демоном.

## Типовой сценарий разработки

1. Запустить демон на тестовом сокете:

```bash
fic --socket /tmp/fic.sock --interval 60
```

2. Запустить GUI с тем же сокетом:

```bash
FIC_SOCKET_PATH=/tmp/fic.sock fic-gui
```

3. Изменить политику в интерфейсе.

4. Проверить состояние через CLI:

```bash
FIC_SOCKET_PATH=/tmp/fic.sock fic-cli policy list all
```

## Важные правила разработки

- Новые действия GUI, которые меняют конфигурацию, должны добавляться через IPC-команды демона.
- GUI может читать данные для отображения, но запись конфигурации должна идти через `fic`.
- Ошибки IPC должны показываться пользователю достаточно подробно, чтобы было понятно, не запущен демон, недоступен сокет или отклонена команда.
- Если добавляется новая daemon-команда, стоит добавить аналогичную диагностику в `fic-cli`, чтобы сценарий можно было проверить без GUI.
